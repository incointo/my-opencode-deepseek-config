# 附录C 校验清单与脚本接口

> 本文档是《英文论文中译处理规范》（README.md）第 5 节校验清单的机械化展开，把各检查项固化为可自动判定的规则、通用校验器接口约定与人工复核子清单。文档工具无关：规则按 docx 结构给出通用取证方式，脚本接口只约定输入/输出契约，不绑定任何特定语言、现成脚本或模型。

## 1. 校验项总表

下表把 README 第 5 节校验清单逐项机械化。`判定规则` 给出可执行判据；`可自动/需人工` 标注该检查能否由脚本完成；`失败处置` 指明问题应回溯到流水线哪个阶段修复（阶段编号对应 README 第 3 节）。

| 编号 | 检查名 | 检查对象 | 判定规则 | 可自动/需人工 | 失败处置 |
| --- | --- | --- | --- | --- | --- |
| C01 | 软换行 | 交付 docx 正文段落 | 解析 `word/document.xml`，统计正文段落内 `<w:br/>`（手动换行符）计数，应为 0 | 可自动 | 回阶段 5 去除软换行，令文本自然回流 |
| C02 | 对齐 | 交付 docx 正文段落 | 不应存在「两端对齐（`<w:jc w:val="both"/>`）且含手动换行」的段落；正文段落对齐宜为左对齐（`left`） | 可自动 | 回阶段 5 改为左对齐，消除字间大空白 |
| C03 | 图注编号完整性 | 图注行文本 | 图注行匹配正则 `^(图 \d+|扩展数据图 \d+|扩展数据表 \d+) \|`；编号从 1 起连续无缺 | 可自动 | 回阶段 4 补齐/修正编号后重排 |
| C04 | 参考文献 | 参考文献区条目 | 条数与原文一致，编号连续无缺 | 可自动 | 回阶段 4 补齐缺失条目、修正编号 |
| C05 | 漏译粗筛 | 译文全文 | 译文 CJK 字数 / 原文词数落在合理区间（约 1.4–2.2）；逐页关键词覆盖核对无缺失页 | 可自动粗筛 + 需人工抽查 | 回阶段 3/4 补译遗漏块 |
| C06 | 重复片段 | 相邻段落 | 相邻段落 n-gram（n=3..5）重复度检测，无整段或长句重复 | 可自动 | 回阶段 4 剔除重复块 |
| C07 | 术语一致 | 译文全文 vs 术语表 | 术语表逐项在译文中命中率 = 100%，无同义混用 | 可自动（命中）+ 需人工（语境核） | 回阶段 3 按术语表重译 |
| C08 | 结构完整 | 交付 docx 对象数 | 图片/公式/表格数量与原文一致；如 docx 内 `<w:drawing>` 数 = 期望图数 | 可自动 | 回阶段 5 恢复缺失对象 |
| C09 | 跨页截断 | 页边界句尾 | 跨页句子由下一块正确续接，页尾无「臆造补全」的完句 | 需人工 | 回阶段 4 忠实续接，删除臆造内容 |

> 编号引用：README 5.1→C01/C03/C04/C06/C09，5.2→C05/C07，5.4→C01/C02/C08。C05、C09 为半自动项，脚本只能给出提示性证据，最终判定需人工确认。

### 1.1 判定细则（算法要点与边界）

- **C01**：统计范围为正文段落（剔除页眉页脚、表格内文本等非正文容器）；`<w:br/>` 无 `w:type` 或 `w:type="textWrapping"` 均计为软换行，`w:type="page"` 不计。
- **C02**：仅当段落 `w:jc` 为 `both` 且同段含软换行时判 fail；纯左对齐段落不告警。若全文无任何 `w:jc` 声明，按默认对齐处理，不判 fail。
- **C03**：先抽取全部图注行，再按三类编号（图/扩展数据图/扩展数据表）分组校验连续性；缺号即 fail，重复编号亦 fail。编号自 1 起，无需与原文编号数值相等，但相对顺序与原文一致。
- **C04**：参考文献条数仅在与原文或期望清单同时提供时才比对；否则只做编号连续自洽检查。
- **C05**：比例阈值（约 1.4–2.2）为粗筛经验值，可用期望清单覆盖；越界判 warn 而非 fail。逐页关键词覆盖由脚本抽每页首尾词生成核对清单，供人工逐页勾选。
- **C06**：只检测相邻段落（含表注、图注）的重合片段；跨章节同模板句（如致谢套话）不计入重复。n-gram 长度取 3–5，避免短词误报。
- **C07**：命中率按「术语表每条至少出现一次其指定译文」计；同一条目在原文中多次出现而译文仅一次时判 warn，提示漏译风险。
- **C08**：期望清单缺失时降级为「图片/表格对象存在性」自洽检查；pdf/md 输入下对象计数按对应解析器规则换算，并在报告中注明口径。
- **C09**：脚本定位页边界句尾并输出上下文，供人工判断「完句是否来自原文」；无法自动判定臆造与否，故标为需人工。

## 2. 脚本接口约定

定义通用校验器（validator）契约，供任意实现落地。契约只约定语义，不约定具体语言或运行环境。

### 2.1 输入

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| 交付文档 | 是 | docx / pdf / md 之一，为校验主对象 |
| 术语表 | 是 | 三列结构（英文原文/中文译文/备注），供 C07 使用 |
| 原文 | 否 | 提供时启用 C05 比例对照、C08 数量对照；缺省时跳过对应检查 |
| 期望清单 | 否 | 期望图数、期望图注编号表、期望参考文献条数等；缺省时仅做自洽性检查 |

### 2.2 输出 JSON 报告

校验器统一输出一份 JSON 报告，顶层字段如下（示例）：

```json
{
  "document": "译文_v1.docx",
  "glossary": "术语表.tsv",
  "source": "原文.pdf",
  "expected": { "drawing_count": 12, "caption_ids": ["图 1", "...", "图 12"] },
  "checks": [
    {
      "id": "C01",
      "name": "软换行",
      "status": "pass",
      "detail": "正文段落 w:br 计数为 0",
      "evidence": ["word/document.xml", "paragraph:12"]
    },
    {
      "id": "C03",
      "name": "图注编号完整性",
      "status": "fail",
      "detail": "图 7 缺失",
      "evidence": ["caption:line 96"]
    }
  ],
  "summary": { "pass": 8, "fail": 1, "warn": 0, "skip": 0 }
}
```

字段约定：

- `checks[].status` 仅取 `pass | fail | warn | skip` 四种取值：`fail` 阻断交付；`warn` 为提示性疑点（需人工确认）；`skip` 表示因缺少原文/期望清单而未运行。
- `checks[].detail` 为人工可读的结论；`evidence` 为定位证据（文件、段落号、行号、样例文本），供回溯阶段修复。
- `summary` 汇总各状态计数，与 `checks` 数组逐条一致。

### 2.3 退出码约定

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部检查 pass（含 skip），无 fail、无 warn 阻断 |
| 1 | 存在至少一个 fail（或经人工判定为阻断的 warn） |
| 2 | 运行错误（文件缺失、解析失败、参数非法），校验未完成 |

### 2.4 命令行示例（伪代码）

```text
check --doc 译文_v1.docx \
      --glossary 术语表.tsv \
      --source 原文.pdf \
      --expected '{"drawing_count":12}' \
      --report report.json
# 退出码：0=全过 1=有fail 2=运行错误
```

约定：报告文件必写（即使运行失败也输出部分报告与错误说明）；任何校验器实现都应支持以上四个输入参数与 `--report` 输出，参数名可等价映射。

### 2.5 报告消费与阶段回溯

校验报告由校验代理（README 第 4 节）产出并归档，消费方按以下约定使用：

- `checks[]` 中任一 `fail`，交付即阻断；按该检查项 `失败处置` 列回溯对应阶段出具缺陷单，修复后重跑校验直至全过（README 阶段间流转规则）。
- `warn` 不阻断交付，但必须由人工在人工复核子清单中确认处置后关闭。
- `skip` 表示本次缺少原文或期望清单，报告 `summary.skip` 计入该数量；交付前应补齐输入消除 skip，否则按未完成对待。
- 归档要求：报告与交付文档、术语表、校验清单勾选结果同批留存，作为审计依据（README 第 6 节「校验报告已归档」）。

### 2.6 阶段回溯映射

| 检查项 | 首次执行阶段 | 失败回溯阶段 | 缺陷单去向 |
| --- | --- | --- | --- |
| C01/C02 | 5 输出重建 | 5 | 合并代理（输出重建） |
| C03/C04 | 4 合并 | 4 | 合并代理（编号） |
| C05 | 4 合并 | 3/4 | 翻译/合并代理（补译/拼接） |
| C06 | 4 合并 | 4 | 合并代理（去重） |
| C07 | 3 分块翻译 | 3（必要时 0） | 翻译代理（按术语表重译） |
| C08 | 5 输出重建 | 5 | 合并代理（恢复对象） |
| C09 | 4 合并 | 4 | 合并代理（续接） |

## 3. docx 取证要点（通用说明）

docx 本质上是一个 zip 容器，校验器按以下通用方式取证（以 .NET / Java / Python 任一解压 XML 皆可，不绑定具体实现）：

- **读取**：解压容器，主内容在 `word/document.xml`；文本、结构、格式均以 XML 元素表达。
- **文本提取**：正文文本取自 `w:t` 元素；`<w:br/>` 为手动换行符，`<w:br w:type="page"/>` 为分页符，计数时应仅统计前者。
- **对齐**：段落对齐在 `w:pPr/w:jc` 的 `w:val` 属性，`both`=两端对齐、`left`=左对齐、`right`=右对齐、`center`=居中；C02 关注 `both` 且含 `<w:br/>` 的段落。
- **对象计数**：图片等对象以 `<w:drawing>` 出现于正文；公式可能为 OMML（`m:oMath`）或对象嵌入；表格为 `<w:tbl>`。C08 据此统计并与期望清单比对。
- **CJK 字数**：用 Unicode 区段 `[\u4e00-\u9fff]` 统计中文字符数，用于 C05 的译文/原文比例粗筛；原文词数按空白切分统计。
- **公式与表格**：OMML 公式位于 `m:oMath` 命名空间，行内公式与显示公式分别取证；表格为 `<w:tbl>`，表内文本不计入正文段落软换行统计（C01 口径）。
- **页眉页脚与批注**：`word/header*.xml`、`word/footer*.xml`、`word/comments.xml` 中的文本与正文分离取证，不参与 C01/C05/C07 统计，避免误报。
- **容错**：解压或 XML 解析失败时按运行错误处理（退出码 2），报告 `checks` 输出为空并附错误说明，不得静默通过。
- **边界**：上述规则以 docx 为准；pdf 需先做文本抽取（按版面 block/栏序），md 直接按 Markdown 解析，取证对象相应替换，判定规则不变。

## 4. 人工复核子清单

以下检查无法可靠自动化，须由人逐项复核并在交付前勾选确认（对应 README 第 6 节验收定义）。

- [ ] M1 跨页截断句由下一块正确续接，页尾无臆造补全（C09 最终判定）
- [ ] M2 术语命中项在上下文中语义正确，无同义词混用（C07 语境核）
- [ ] M3 图表引用格式统一为「（图 N）」「（扩展数据图 N）」「（扩展数据表 N）」
- [ ] M4 缩写首现写法为「中文名（English Full Name, ABBR）」，后续统一用缩写
- [ ] M5 公式、交叉引用等不译物以占位符形式原样保留，未被误改
- [ ] M6 GB/T 15834 标点用法（书名号、引号、顿号、省略号等）复核
- [ ] M7 GB/T 15835 数字用法、GB/T 7714 参考文献著录格式复核
- [ ] M8 双语对照版式正确，原文与译文一一对应，图表对象未移动或破坏
